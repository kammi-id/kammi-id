# Design: Image Upload for Branches and Members Forms

## Overview
Implementation of an image upload system for organization logos (branches) and member photos. The system uses a "Pre-upload & Path-save" approach to ensure a responsive user experience and efficient storage management using S3/MinIO.

## Goals
- Allow users to upload and preview images for branches and members.
- Implement a seamless "instant upload" experience.
- Optimize storage by updating existing files instead of creating duplicates.
- Prevent storage bloat by cleaning up orphaned files when forms are cancelled.

## Technical Approach

### 1. Storage Strategy: "Instant Upload"
Instead of sending binary data during the final form submission, images are uploaded to S3 immediately after selection. The form then stores the resulting file path as a string.

- **Creation:** If no existing path is provided, a new file is created in S3.
- **Update:** If an existing path is provided, `storage.updateFile` is used to overwrite the existing object, maintaining the same filename.
- **Retrieval:** Images are displayed using signed URLs generated by `storage.getSignedUrl`.

### 2. Backend Implementation

#### New Server Actions (`src/lib/actions/storage.ts`)
- `uploadImageAction(formData: FormData)`
  - Extracts file and optional `existingPath`.
  - If `existingPath` exists $\rightarrow$ calls `storage.updateFile(existingPath, file)`.
  - If no `existingPath` $\rightarrow$ calls `storage.uploadFile(file, folder)`.
  - Returns the final storage path.
- `deleteImageAction(path: string)`
  - Calls `storage.deleteFile(path)`.
  - Returns success status.

#### Integration with Form Actions
- `saveBranch` and `saveMember` actions will be updated to accept the image path (string) and update the corresponding DB column (`logo` for organizations, `photo` for members).

### 3. Frontend Implementation

#### `ImageUpload` Reusable Component
A standalone component to handle the upload lifecycle:
- **Inputs:** `value` (current path), `onChange` (callback), `label`.
- **Logic:**
  - Handles file selection $\rightarrow$ triggers `uploadImageAction`.
  - Manages local loading state during upload.
  - Provides instant preview using `URL.createObjectURL` and signed URLs for existing images.

#### Form Integration (`add-form.tsx`)
- **State Management:** Update Zod schemas to include optional `photo`/`logo` strings.
- **UI:** Embed `ImageUpload` in the member and branch creation/edit forms.
- **Cleanup Logic:**
  - Use a `useEffect` or "Cancel" handler to track newly uploaded files.
  - If the form is closed/cancelled and a new file was uploaded (without an `existingPath`), call `deleteImageAction` to remove the orphaned file from S3.

## Success Criteria
- [ ] Users can upload images for branches and members.
- [ ] Previews are displayed immediately after upload.
- [ ] Updating an image doesn't create a new file in S3.
- [ ] Cancelling a form removes newly uploaded files from S3.
- [ ] No runtime errors during the upload/save flow.
