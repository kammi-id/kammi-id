Problem

Solution

Problem

ADR-0001's rule is enforced only in the browser, and add-form already violates it with three uncoupled Switches. The derivation ladder is copied four times, one copy inconsistently.

Solution

A Keadaan module: one type, one parse from the three columns, one serialize back, one SQL filter. Write paths take a Keadaan, not three booleans.

Wins

  • • locality: ADR-0001 becomes enforceable, not advisory
  • • the illegal combination stops being representable
  • • leverage: 4 ladders and 8 SQL fragments collapse
  • • interface is the test surface — currently untestable
This is ADR-0001's stated consequence, not a re-litigation: "Siapa pun yang menambah jalur tulis baru ke Keadaan Kader wajib menegakkannya sendiri." The module is how that stops depending on memory. The schema stays as-is — three booleans, no migration — so nothing about the production decision changes.

Problem

Three implementations of one identity rule, none tested directly. The lib copy reads-max-then-increments outside its caller's transaction, and there is no UNIQUE constraint on register_number — a collision is stored silently.

Solution

One module, transaction-aware by construction. The seed script and bulk upload call it rather than re-deriving it.

Wins

  • • interface is the test surface — currently untested
  • • seed stops drifting from production
  • • surfaces the missing UNIQUE constraint
Production data. Adding a UNIQUE constraint is a separate decision from the module and may fail on existing rows — check for duplicates first, and it needs a migration, which is your call.

Problem

CONTEXT.md says Kelulusan is what raises Jenjang Kekaderan and grants Perangkat certification. In code it writes one boolean on a join row and nothing else — both are set by hand, in three UI surfaces each.

Solution

Either a module that owns the consequence of Kelulusan, or an ADR recording that promotion is deliberately manual. Right now the glossary and the code disagree and neither is marked as authoritative.

Not an architecture call — a product one, and it touches production data. Flagged because a future reader of CONTEXT.md will assume the edge exists. Related: profile-header.tsx:60 and profile-sidebar.tsx:100 both check Daurah attendance while ignoring isPassing — an attended-but-failed DPMK clears the Sertifikasi Tanpa Riwayat warning.

Top recommendation

1. Give Masa Penetapan Kelulusan a module

It is the smallest complete instance of the shape candidates 2, 3 and 4 repeat at larger scale — a domain rule with a name in CONTEXT.md and no module to hold it. It already has the best test coverage in the repo (eight cases), so the deepening happens under a net rather than beside one. And it closes defect #3 by construction: removeAttendantAction cannot forget a gate it has to call to compile. Do this one first to establish the pattern, then take candidate 3 — Cakupan — which is where the live exposure is.

The three defects in the header are not refactors and should not wait for one.
